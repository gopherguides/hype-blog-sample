## Overview

Great technical documentation is invisible when it works. Users find what they need, understand it immediately, and move on. This article explores the principles behind documentation that achieves this goal.

---

## Know Your Audience

Before writing a single word, answer these questions:

- **Who will read this?** Beginners, experts, or both?
- **What problem are they solving?** Documentation should be task-oriented.
- **What do they already know?** Don't explain what's obvious; don't assume what isn't.

The best documentation meets users where they are, not where you wish they were.

## Structure Matters

Good structure helps readers navigate quickly:

1. **Start with the outcome** - What will users accomplish?
2. **Provide quick starts** - Let experienced users dive in
3. **Layer complexity** - Basic usage first, advanced topics later
4. **Use consistent patterns** - Same structure across similar pages

A reader should know within seconds whether they're in the right place.

## Write for Scanning

Most readers scan before reading. Support this behavior:

- **Use descriptive headings** - "Installing on macOS" not "Installation"
- **Lead with the important part** - Front-load sentences with key information
- **Keep paragraphs short** - 3-4 sentences maximum
- **Use lists** - They're easier to scan than prose

## Show, Don't Just Tell

Code examples are worth a thousand words:

- **Make examples runnable** - Copy-paste should work
- **Use realistic data** - Not "foo" and "bar"
- **Show common patterns** - What users will actually do
- **Include expected output** - Help users verify success

## Maintain Ruthlessly

Documentation rots faster than code:

- **Review with each release** - Features change, docs must follow
- **Delete aggressively** - Outdated docs are worse than none
- **Test your examples** - Automated testing catches drift
- **Listen to users** - Their confusion reveals gaps

## The Documentation Mindset

Writing documentation is a form of empathy. You're helping future users (including future you) solve problems efficiently. Every minute spent on clear docs saves hours of confusion later.

The best documentation authors remember what it felt like to not understand something. They channel that memory into explanations that illuminate rather than obscure.

## Key Takeaways

1. **Write for tasks** - Users have goals, help them achieve those goals
2. **Structure for navigation** - Make finding information effortless
3. **Show working examples** - Code speaks louder than descriptions
4. **Maintain continuously** - Documentation is a living system
5. **Embrace feedback** - User confusion is a documentation bug
